# 分层文本润色

在每轮翻译初稿完成后、独立一致性审查前，润色本轮新增或实质改写的中文字符串。润色是表达编辑，不是重译：英文原文决定含义，已锁定术语、用户参考和目标文件中的同实体用法约束译法。润色不得补写原文没有的信息、删去原文信息、改变规则效果或扩大翻译范围。

## 分类方法

按字符串逐条分类，不按整份文件分类。每条先判断实体/领域，再判断内容功能；将两者一并提供给适用 prompt。分类证据优先级如下：

1. JSON 顶层实体键、文件路径及实体字段（例如 `bestiary/*.json` 的 monster、`adventure/*.json` 的 adventure、`book/*.json` 的 book、`fluff-*` 与对应实体）确定领域。
2. JSON 结构和路径确定内容功能：`trait`、`action`、`reaction`、`legendary`、`spellcasting` 等规则字段通常属于规则/效果；`entries`、`entriesHigherLevel`、`fluff`、`readaloud`、`inset`、`quote`、`table`、`list` 等按对象类型、标题和局部语义判断。
3. 当前英文内容决定最终功能。同一 `entries` 字段可包含规则、叙事、对白或程序性说明，不得仅凭字段名推断。

常见领域包括怪物；法术；职业、子职及其特性；物品、物品属性与精通；专长、背景、种族及其他角色选项；状态、疾病、陷阱、危害、动作、变体规则等规则实体；冒险正文；规则书正文；各实体的 fluff/背景描述。实体目录和顶层键的完整索引见仓库 `docs/entity-json-search-guide.md`。不要为每种实体复制一套同义 prompt：领域 prompt 只提供该领域的术语和准确性限制，内容功能 prompt 负责文字表达标准。

内容功能至少区分：

- **规则与效果**：定义、条件、特性、动作、法术、物品效果及程序性规则文本。
- **叙事正文**：冒险/规则书中的场景叙述、设定说明、主持人说明和背景介绍。进一步按用途标注为叙述、主持人指引或背景描述；不确定时标为一般叙事。
- **朗读文本与对白**：明确供主持人朗读的文本，以及角色直接说出的台词。保留说话者、语气、信息揭示顺序和引号内外边界。
- **名称、标题与短标签**：实体名、章节/条目标题、表格标题、选项名及类似短文本。优先保证简洁、辨识度和跨引用一致。
- **表格及列表内容**：按单元格/列表项独立处理；保持行列、顺序、骰值、范围、单位和分支条件不变。

如果一个字符串混合两种功能，以其主功能选 prompt，提示模型保护嵌入的另一种内容（例如叙事中的规则术语或对白中的专名）。若分类证据冲突或无法可靠判断，使用“通用保守润色”，只修正明显不通顺或有歧义的中文，不改变句式功能、语气和信息组织；记录此回退，不要猜测。

## Prompt 组成与分类专用要求

每条润色 prompt 都包含以下共同输入：实体/领域、JSON 路径、内容功能、英文原文及必要上下文、中文初稿、锁定术语/用户参考，以及本文件的通用约束。只给模型当前字符串和理解该字符串所需的邻近上下文；不要让它重写整个实体或文件。要求返回润色后的字符串；若无明确可改进之处则原样返回。不得要求输出或修改 JSON。

在共同约束之外，追加与内容功能对应的指令：

### 规则与效果 prompt

> 以规则准确和无歧义为首要目标。改善中文语序和指代，但保留定义术语及其区分、施事/受事、条件和例外、目标与范围、距离、持续时间、时点、次数、数值、骰式、动作经济及效果强弱。不得文学化、压缩重复机制或把隐含条件改成确定事实。保留全部 5etools 标签及其类型、参数、顺序和路由信息；只可润色标签外自然语言及允许本地化的显示文本。

怪物规则文本额外使用 [bestiary-xmm-style.md](bestiary-xmm-style.md) 的措辞和术语约束；必要时检索同机制的 XMM 中英对照。法术、职业特性、物品、陷阱等遵循同实体已有译法和全局术语，不得把怪物专用句式机械套到其他规则领域。

### 叙事正文 prompt

> 使中文自然、清楚且符合原文叙述视角和语气。保留事件、因果、空间关系、时间顺序、人物动机、设定事实、线索强弱及不确定性；不得增加氛围细节、替作者解释或改变信息揭示顺序。主持人指引应清楚可执行，避免改成角色视角叙述。遇到规则术语或引用实体名时保持术语表译法。

### 朗读文本与对白 prompt

> 保持可直接朗读的流畅度、节奏、语气和原文情绪。对白保留说话者身份、口吻、言外之意及信息量，不擅自添加解释或改写成转述。朗读文本保持面向玩家的视角；不得泄漏相邻主持人说明中的隐藏信息。按中文引号规范处理直接引语，并保留原文段落边界及标签结构。

在 5et 冒险文件的专用润色轮次中，忽略上述 prompt 中的引号字形要求：保留现有引号，不以引号样式提出润色建议。部署阶段会统一处理引号。

### 名称、标题与短标签 prompt

> 优先复用同一实体、同类别术语和已有目标译名。名称及标题应简洁、易辨认并适合所在 UI/章节层级；不要将说明性正文塞进标题，不得改变专名、来源标识、交叉引用或标识符。没有可靠译名时保留已有处理或使用有依据的音译，不凭风格偏好造新译名。

### 表格及列表 prompt

> 保持各单元格或列表项简短且平行。严格保留项目数量、顺序、对应关系、骰值、数值范围、单位、条件和分支；不得合并、拆分、移动或遗漏项目。列标题可适度压缩，但含义必须与各列数据一致。

### 通用保守润色 prompt

> 在不改变当前中文含义、信息顺序、语气、结构或术语的前提下，只修正明确的语病、重复赘词或妨碍理解的直译腔。若没有确定的问题，原样返回；不要为追求文采重写。

## 通用保护约束

- 只处理本轮翻译范围内已翻译或实质修订的字符串。homebrew 的分析器 job 是文本处理边界；chunked homebrew 只处理获分配 JSON pointers。可为理解读取相邻上下文，但不得编辑范围外内容。
- 不改变 JSON 键、结构、类型、数组顺序、身份字段、机器值、标签语法、链接路由、变量、代码、公式、骰式、数字、单位、源缩写或 URL。不得为改善文风而移动标签或机器文本。
- 保留现有目标文件对术语、标点、专名和排版的局部一致性；统一执行 `localization-rules.md` 中适用的中文引号要求。
- 仅有个人文风偏好、没有语义或规范依据时，不强行改写已有通顺译文。润色结果与初稿相同时不算实质改动。
- 润色后重新解析 JSON。随后独立审查仍须按完整累积翻译范围检查语义和机械准确性；不得因润色阶段已自检而省略审查。独立审查不应仅凭主观文风偏好要求改写，但应指出违反上述分类标准或导致表达歧义/失真的具体问题。

## Chunked homebrew

每个 chunk worker 只对其租赁 pointers 中本轮翻译的字符串分类和润色。将实体类别、内容功能和使用的专用标准作为该 chunk 的审查上下文；完整翻译/润色轮次统一计入已有 `review.rounds`。最终全文件独立术语/内容审查还要检查不同 chunk 对同类内容是否保持表达和术语一致，但不得仅为统一文风而覆盖范围外的既有文本。

## 5et 冒险文件的独立润色组

仅当源文件位于 `data-bak/adventure/` 时，在主翻译完成后、常规独立一致性审查前，启动至少两名全新的只读润色子智能体。此要求不扩展到 bestiary、book、homebrew 或其他路径。润色子智能体不得兼任本轮翻译者或之后的一致性审查者。

### 分工和输入

- 主智能体按稳定 JSON Pointer 或章节/区域将本轮新增或实质修改的字符串划分为互不重叠的批次，分配给润色组成员。每名成员只负责获分配的范围；文本较少时仍需至少两名成员，可按段落分开。
- 每名成员接收其范围内的英文原文、必要的相邻上下文、中文初稿、锁定术语和用户参考，以及对应的实体/内容功能分类与本文件适用的润色 prompt。不得只给孤立中文句子，也不得让成员重写整份文件。
- 子智能体只读源文件和目标文件，不得直接编辑、格式化、提交，也不得扩大翻译范围。它们的任务是提出可选的中文表达修改，不是复核术语或机械准确性的替代流程。

### 返回内容与采纳

每名成员按稳定位置逐条返回以下内容：对应的英文短语、当前中文、建议中文、具体的语言问题及其如何改善可读性、置信度（高/中/低）和语义风险（无/可能有）。只报告有明确问题的字符串；不接受只写“更自然”等泛泛理由的建议。若一个建议可能改变事实、细节、时序、地点、数量、程度或规则含义，应标为“可能有”并说明依据；证据不足时只指出疑点，不提供看似定稿的替换句。建议应尽量局部修改，不重写整段。不同成员处理范围不重叠，因此无需合并相互冲突的版本。

每名成员还要对获分配文本做一次只看中文的通读，检查搭配、赘词、重复和并列项是否自然。特别留意中文中存在上下位关系的词，避免把泛称和其下位类别生硬并列；例如英文 `sheep and goats` 应译作“绵羊和山羊”，不能机械写成“羊和山羊”。若原文列举了不同类别，应通过精确译名保留区分，不要为求顺口而合并信息。

主智能体逐条对照英文和上下文，特别核对建议是否保留原文的限定条件、数量和单位、程度、地点、时点、目的、状态，以及信息的确定性；确认没有增加、遗漏或改变信息、视角、人物语气、规则含义、线索强弱、顺序或术语后，才可采纳。随后再只看中文通读改后句子，确认没有类别重复、赘词或生硬搭配。仅属个人文风偏好、未改善明确问题的建议应拒绝。语义风险为“可能有”的建议不得直接采纳，需先查明原文证据；证据无法消除歧义时保留原译或记录待裁定问题。主智能体自行应用被采纳的修改，并记录未采纳的实质建议及简短理由。应用修改后检查 JSON Pointer 对应内容的差异，并确认没有意外缩进、标点以外结构或其他格式变化。所有引号字形均不属于此润色任务；保留原样，交由部署阶段统一处理。

润色提案处理完后重新解析 JSON，再按 [subagent-review.md](subagent-review.md) 执行常规独立一致性审查。审查者必须是新的子智能体，且不得属于润色组。对于 `data-bak/adventure/` 来源，审查者跳过引号字形检查；所有实质润色改动仍须接受完整语义、术语和机械内容审查。若审查后再改动中文，照常启动新一轮独立一致性审查。
